# Repository Reorganization Plan

This repository contains strong experimental material, but it is currently hard to navigate because code, raw outputs, publication figures, exploratory plots, notebooks, and interactive demos are mixed together. The goal of this reorganization plan is to make the repository read like the experiment section of a strong paper: clear entry points, explicit experiment groups, easy reproduction paths, and a clean separation between curated artifacts and raw/generated artifacts.

## Goals

1. Make the repository understandable in under 2 minutes.
2. Make reproduction possible by following a short, linear README.
3. Separate:
   - core code
   - experiment runners
   - curated paper figures
   - raw outputs
   - interactive demos
   - exploratory / archival material
4. Reduce the "AI-generated showcase" feeling of the README and replace it with a paper-style structure.
5. Keep unique visual assets, but highlight only the most important ones.

## Content organization rules

### 1. `code/` or future `src/`
Keep only reusable implementation code and main experiment entry scripts here.

Should stay:
- `robust_losses.py`
- `vision_transformer.py`
- clean experiment runners
- plotting scripts that are still actively used

Should move out eventually:
- one-off notebooks
- archived or alternate framework runs if not central
- historical scripts with dates in filenames unless necessary for provenance

### 2. `results/paper_figures/`
Only the figures that appear in README or paper-style summary.

Examples:
- combined PathMNIST/DermaMNIST noise plot
- FGSM robustness plot
- S-divergence heatmap / surface
- clean-vs-robust frontier
- one summary multi-panel figure

This folder should be small and curated.

### 3. `results/raw_outputs/`
Store all generated CSVs, seed-wise outputs, intermediate plots, and per-run artifacts.

Examples:
- every seed output
- every single dataset/loss curve
- logs and temporary images

### 4. `results/exploratory/`
Keep useful but not core visuals here.

Examples:
- early MNIST plots
- CIFAR sanity checks
- parameter sweep variants not used in final story
- draft figures with alternative styles

### 5. `docs/figure_guide.md`
Create a mapping like:
- Figure 1 → main label-noise result → file path → generated by script
- Figure 2 → FGSM result → file path → generated by script
- Figure 3 → parameter surface → file path → generated by script

This makes the repo feel like a paper supplement rather than a dump.

## README redesign principles

The current README is visually impressive but too long, too dense, and too promotional. It should be rewritten around a paper-like flow.

### Recommended README structure

1. Title and one-sentence contribution
2. What this repo contains
3. Main experimental findings
4. Repository map
5. Reproduce the main figures
6. Run each experiment family
7. Interactive visualizations
8. Selected results only
9. Citation

### Recommended tone

- more precise
- less hype
- fewer badges/GIFs at the top
- fewer claims in checkmark style
- more emphasis on what is reproduced where

### Suggested README opening

> This repository studies robust neural learning with S-Divergence losses across three settings: (1) Vision Transformers on MedMNIST image classification, (2) BERT-based clinical NLP, and (3) zero-shot multimodal medical classification with CLIP/MedSigLIP. It includes experiment code, curated figures, raw outputs, and browser-based interactive visualizations.

That kind of opening is calmer and more academic.

## Recommended README sections to remove or compress

- overly long hero banner
- too many GIFs before the reader understands the project
- long gallery of every figure in the main README
- future-looking sections that are not yet available
- repeated claims that should instead appear as concise bullet findings

## Recommended README sections to keep

- short theory section for SDIV
- exact scripts to reproduce main results
- one concise results table for each experiment family
- one clear repository structure block
- links to interactive demos

## Visual cleanup guidance

### For interactive plots
Adopt a consistent academic theme:
- white background
- near-black text
- light gray gridlines
- restrained, publication-style colors
- less neon contrast
- cleaner legends and annotation boxes

### For static results folders
Use naming like:
- `fig1_pathmnist_noise.png`
- `fig2_dermamnist_fgsm.png`
- `fig3_sdiv_surface.png`
- `fig4_frontier.png`
- `figS1_mnist_sanity_check.png`

This immediately communicates importance.

## What "great paper experiment section" means for this repo

A visitor should quickly answer:
- What is the method?
- What are the datasets?
- What are the main experiment groups?
- Which figures matter most?
- How do I reproduce Figure 1 / 2 / 3?
- Where are raw outputs vs curated outputs?

That is the standard this reorganization is aiming for.
